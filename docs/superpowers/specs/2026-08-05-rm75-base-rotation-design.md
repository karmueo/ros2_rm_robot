# RM75 底座扫转示教设计

## 目标

在 `moveit_rm75.launch.py` 启动的 RM75 MoveIt 示例中，先执行一段与真实 RM75 关节限位一致的底座扫转示教，再继续执行现有示教流程：

1. 保持其余关节的当前值，将 `joint2` 运动到 `+90°`，使机械臂处于用户要求的水平姿态。
2. 保持其余关节不变，将 `joint1` 运动到 `-3.1 rad`（约 `-177.6°`）。
3. 将 `joint1` 从 `-3.1 rad` 单向运动到 `+3.1 rad`，完成约 `355.2°` 的最大允许扫转。
4. 扫转成功后，继续执行现有启动关节目标、可选笛卡尔示教及回零流程。

严格的同方向 `360°` 连续旋转超出真实 RM75 当前 URDF 中 `joint1=-3.1～3.1 rad` 的限位。因此本功能不修改关节类型或限位，以最大允许扫转代替完整一圈。

## 接口与结构

在 `moveit_rm75.launch.py` 中新增布尔启动参数 `enable_base_rotation_demo`，默认值为 `true`，并将其传给 `simple_moveit_node`。其他型号的启动入口不默认启用该动作，避免改变 ECO63 和 RX75 的行为。

`LinearMotionNode` 声明同名参数，默认值为 `false`。这样只有 RM75 启动文件显式传入时才启用新流程，直接运行节点或从其他 launch 启动时保持兼容。

`simple_moveit_node.cpp` 在读取当前关节状态后、现有启动姿态逻辑前执行扫转。目标向量以当前关节值为基础，只修改指定关节，避免无意移动其余轴。关节通过活动关节名称定位，不依赖固定数组下标；缺少 `joint1` 或 `joint2` 时视为配置错误并停止。

## 动作与数据流

启用参数后，程序按以下顺序调用现有的 `moveToJointTarget`：

1. `joint2=π/2`；
2. `joint1=-3.1`；
3. `joint1=+3.1`。

每次目标均继承上一步目标值，使 `joint2` 在底座扫转期间维持 `+90°`。第三步结束后进入原有逻辑，原有启动目标会自然把机械臂调整到既定姿态。

未启用参数时，程序完全跳过以上三步，行为与当前版本一致。

## 错误处理与安全性

- 任何一步规划或执行失败，记录具体动作上下文，关闭节点并返回失败，不继续运行后续示教。
- 找不到 `joint1` 或 `joint2` 时明确报错，不以关节数量或下标猜测关节。
- 不修改 RM75 URDF、SRDF、控制器或 MoveIt 关节限位。
- 目标使用 `3.1 rad` 而不是数学上的 `π rad`，确保不超过真实模型限位。

## 测试与验证

测试应首先验证新行为不存在时会失败，然后实现最小改动使其通过。覆盖内容包括：

- RM75 launch 声明 `enable_base_rotation_demo=true` 并以布尔参数传入节点。
- 节点通用默认值为 `false`，避免影响其他启动方式。
- 扫转目标按 `joint2=π/2`、`joint1=-3.1`、`joint1=+3.1` 的顺序生成。
- 目标按关节名称修改，非目标关节保持原值。
- 缺少必要关节时拒绝执行。
- 新示教关闭时保持原流程。

完成实现后运行相关单元测试、Python launch 文件语法检查，并构建 `rm_moveit2` 功能包。若本机具备完整 ROS 2/MoveIt 运行环境，再进行 launch 级仿真验证。
